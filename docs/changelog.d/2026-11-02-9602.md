- nginx: the explorer upload relay gets its own location with a 40m body cap
  (system_3 #9602, #4121-B2): `/admin/explorer/api/uploads/` takes a 32 MiB
  part; the rest of the explorer API keeps 25m. The admin gate's
  `/_internal/verify-admin` now carries a 100m cap: it checked every gated
  request's body size against the server's 25m and answered 413 inside its
  subrequest, which nginx returns as a 500, so a Penpot upload over 25m failed
  despite Penpot's own 100m. `scripts/upload-cap-probe.sh --docker` proves
  each cap against this config in nginx:alpine.
- nginx: the upload relay streams each part to explorer-api
  (`proxy_request_buffering off`, HTTP/1.1 upstream) instead of spooling it to
  `client_temp`, which on the cell is the unencrypted root volume (system_3
  #9602, security review). `upload-cap-probe.sh` pins both directives and, under
  `--docker`, checks nginx logged no temp-file spool for an uploads request.
